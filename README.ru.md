**Keno BOT** — локальный исследовательский стенд и бот автоматических ставок **только для Keno**.

* Полностью пересчитывает локально цепочку **доказуемо честной игры** (`server_seed` / `client_seed` / `nonce`, HMAC-SHA256) и совпадает с официальным калькулятором побайтово — это проверяется одной командой.
* Проверяет все **40 комбинаций официальной таблицы выплат** по одной (измеренный RTP 98.65% – 99.07%).
* Измеряет стратегии **нулевой моделью** (честное гипергеометрическое распределение), то есть показывает **форму распределения результатов**, а не скриншот с выигрышем.
* И только если вы сами включите — может управлять **вашим собственным аккаунтом** через **ваш собственный Chrome** (CDP). По умолчанию это чистая симуляция, реальные деньги требуют явного включения.

Только Keno. Никаких предсказаний, никакого ИИ-подбора чисел и никаких обещаний дохода.

## Чем отличается от обычных скриптов для Keno

| Обычный скрипт | Keno BOT |
| --- | --- |
| Молоток: горячие числа, догон холодных, мартингейл | Сначала линейка: RTP одной ставки, дисперсия и матожидание считаются локально |
| Выплаты передаются на словах | Все 40 официальных комбинаций пересчитаны и сопоставлены с собственной таблицей |
| ГСЧ можно только «доверять» | Цепочка HMAC-SHA256 пересчитывается локально, байт в байт с официальным калькулятором |
| Доказательство — скриншот | Во всех режимах полный журнал: оборот, возврат, просадка, серии, перцентили |
| Только ручные нажатия | Лестница сумм + дисциплина сессии + паузы по фрагментам + стоп-лосс/тейк-профит, полностью автоматически |

## Быстрый старт

### A. Запустить exe (Python не нужен)

1. Скачайте `KenoBOT.exe` со страницы [Releases](../../releases).
2. Запустите двойным щелчком: поднимется локальная страница на `127.0.0.1` и откроется браузер.
3. Два экрана: `/` — тренировочный стенд (чистая симуляция), `/live` — живой стол (деньги двигаются только после подключения и включения тумблеров).

При первом запуске создаётся `%LOCALAPPDATA%\KenoBOT` для состояния, логов и отчётов. Реестр не трогается, службы не ставятся; удалить папку — значит удалить всё.

### B. Запуск из исходников (для разработчиков)

```bash
git clone <your-fork-url> keno-bot && cd keno-bot
python -m pip install -e .
python keno_bot_app.py        # то же, что python -m keno.cli serve
```

В Windows можно дважды щёлкнуть `启动.bat`: если есть `dist\KenoBOT.exe`, запустится он, иначе — локальный Python.

### C. Собрать exe самостоятельно

```powershell
powershell -ExecutionPolicy Bypass -File build_exe.ps1            # один файл dist\KenoBOT.exe
powershell -ExecutionPolicy Bypass -File build_exe.ps1 -Onedir   # вариант папкой, стартует быстрее
powershell -ExecutionPolicy Bypass -File tools\make_release.ps1  # exe + документация -> dist\KenoBOT-<version>-win64.zip
```

## Как подключить живой стол (реальные деньги, по умолчанию выключено)

Keno BOT не хранит ваши логин и пароль и не имеет своей формы входа. Он делает одно: подключается к Chrome, где вы **уже вошли** (Chrome DevTools Protocol), берёт токен сессии из запросов самой страницы (только в памяти, никогда на диск) и нажимает кнопки ставок как человек.

```bash
# 1) Запустите Chrome с портом отладки (свой профиль)
chrome.exe --remote-debugging-port=9222 --user-data-dir=%USERPROFILE%\keno-chrome-profile

# 2) Вручную войдите в этом Chrome и откройте страницу Keno

# 3) Проверка только на чтение: подключиться и посмотреть, не ставя
python -m keno.cli live connect --cdp http://127.0.0.1:9222

# 4) Ставить — только добавив --live-bets и начиная с минимальной суммы
python -m keno.cli live run --cdp http://127.0.0.1:9222 --live-bets --risk low --pick-count 10 --rounds 20
```

`KENO_CHROME_PROFILE` / `KENO_CHROME_PS1` задают профиль Chrome и скрипт запуска; без них используются значения по умолчанию в `~/.keno-bot/`.

Дисциплина живёт в коде, а не в документации: лимит на ставку, ступени, понижение после двух поражений подряд, обязательный отдых после выигрыша на четвёртой ступени, стоп-лосс/тейк-профит, паузы между фрагментами и дневной лимит.

## Доказуемая честность (локальный пересчёт байт в байт)

Каждый раунд восстанавливается из трёх публичных величин: `server_seed` (сначала публикуется хеш, потом раскрывается сид), `client_seed` (можно менять) и `nonce` (номер раунда).

```bash
# Встроенный самотест (240 раундов, сиды существуют только в этом репозитории)
python -m keno.cli verify-rounds --replay-file data/samples/rounds_sample.jsonl --seeds-file data/samples/seeds_sample.json
```

Ожидаемый вывод — `240/240 rounds PASS`. Измените один символ сида, и сразу FAIL: именно это доказывает, что проверка настоящая.

## Аудит таблицы выплат

| Вариант | Измеренный RTP |
| --- | --- |
| low, 10 чисел | 98.76% |
| Все 40 комбинаций | 98.65% – 99.07% |

Собственная таблица `configs/payout.yaml` отличается от официальной на 5/6/7/8/9 попаданиях; полный список — в `reports/payout_audit.md`. Пересчитать самому:

```bash
python -m keno.cli audit-payouts --paytable configs/payout.yaml --official data/reference/stake_keno_payouts_official.json
```

## Что измеряет этот инструмент

* **Матожидание для любого варианта**: `выплата × P(попадание) − ставка`, считается прямо по гипергеометрическому распределению, без симуляции.
* **Дисперсия и просадка стратегии банкролла**: Монте-Карло на честных розыгрышах, с фиксированным зерном и воспроизводимым результатом.
* **Серии и распределение попаданий**: сравнение с теорией (хи-квадрат по гистограмме попаданий).
* **Проверка с замороженными параметрами**: параметры, настроенные на одном отрезке, воспроизводятся на невиданном материале сидов, чтобы исключить запоминание шума.

Keno платит меньше ставки в любом варианте. Управление банкроллом меняет только **форму** распределения (просадку, скорость разорения, волатильность), но не знак. Ценность этого репозитория — измерить это, а не рассказать как историю.

## Структура проекта

```text
keno_bot_app.py           лаунчер / точка входа PyInstaller
build_exe.ps1             сборка exe
configs/                  game.yaml (поле, протокол ГСЧ) payout.yaml (свои выплаты) bot_phase.yaml (ступени)
data/reference/           официальная таблица выплат
data/samples/             самотест-выборки
src/keno/provably_fair/   HMAC-SHA256, генерация float, проверка раундов
src/keno/game/            розыгрыш, попадания, выплаты, расчёт
src/keno/bot/             бот: банкролл, фазовая машина, комбинированная стратегия, журнал, CDP/живой запуск
src/keno/research/        Монте-Карло, проверка замороженных параметров, сетка риска
src/keno/reporting/       метрики (гипергеометрика, хи-квадрат, просадка, серии) и экспорт отчётов
src/keno/webapp/          локальный рабочий стол (HTTP-сервер + страницы)
tools/                    генерация выборок, иконок, релизов
docs/                     архитектура, методика проверки, быстрый старт на китайском
tests/                    pytest (110 тестов)
```

## План развития (PR приветствуются)

* **Скриптовые плагины стратегий**: стабильный хук (получает историю и баланс, возвращает числа и сумму), чтобы логику можно было добавлять без правок ядра.
* **Сверка со списком ставок**: после сбоя или таймаута сверяться со списком ставок платформы и восстанавливать журнал.
* **Английский интерфейс**: тексты страниц пока в основном на китайском; после i18n будет удобнее зарубежным контрибьюторам.
* **Валидация данных**: JSON Schema для `data/**/*.jsonl` и проверки полей в `collect`.
* **Кроссплатформенность**: собрать все личные пути в `keno/paths.py` и переменные окружения (включая запуск Chrome в macOS/Linux).
* **Реальный источник WebSocket**: `src/keno/bot/ws.py` пока только каркас.
